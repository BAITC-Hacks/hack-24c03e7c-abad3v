# AI Sana — hackathon MVP

Общий проект команды AbaD3v: React/Vite frontend в корне и Node.js backend в `server/`. API и типы описаны в [shared/CONTRACT.md](shared/CONTRACT.md), продуктовый план — в [HACKATHON_PLAN.md](HACKATHON_PLAN.md).

## Запуск

Нужен Node.js 24.x с `node:sqlite`. Установка выполняется из корня проекта через npm workspaces.

```powershell
npm.cmd install
npm.cmd run seed
npm.cmd run dev
```

Сценарий `npm run dev` запускает backend и Vite одновременно. Откройте адрес Vite из терминала (обычно `http://localhost:5173`). API работает на `http://localhost:3001`; проверка: `http://localhost:3001/api/health` возвращает `{"status":"ok","db":"ok"}`. Vite проксирует `/api` на порт 3001. Интерфейс по умолчанию использует настоящий локальный API и автоматически выбирает демо-профиль. Демо-профили создаются при старте сервера; `seed` можно повторять без дублирования задач и откликов.

Если нужен только один сервис, используйте:

```powershell
npm.cmd run dev:server
npm.cmd run dev:client
```

Если запуск сообщает, что порт 3001 уже занят (`EADDRINUSE`), предыдущий backend ещё работает. Для полного перезапуска нажмите `Ctrl+C` в прежних терминалах backend и Vite, затем один раз выполните `npm.cmd run dev` из корня. Если нужно добавить только frontend к уже работающему backend, используйте `npm.cmd run dev:client`. Проверить работающий API можно по `/api/health`; предупреждение об экспериментальном SQLite не является ошибкой запуска.

Если нужен автономный просмотр интерфейса без сервера, скопируйте корневой `.env.example` в `.env.local` и задайте `VITE_API_MODE=mock`. После изменения перезапустите Vite. Mock содержит синтетические данные и не сохраняет действия на backend.

## Данные из CSV

Начальное наполнение сервера и автономного frontend берётся из одних файлов:

| Файл | Содержимое |
|---|---|
| `demo/profiles.csv` | Команды, интересы, навыки и технологии |
| `demo/tasks.csv` | Исходные описания, темы и отрасли задач |
| `demo/cards.csv` | Структурированные карточки, полнота и опубликованное состояние |
| `demo/applications.csv` | Отклики команд, ссылки и решения бизнеса |

Пустые ячейки карточек превращаются в `null`. Общий загрузчик `shared/demo-data.js` проверяет ID, связи задач с командами, статусы и разбивку рейтинга. Ссылки на `example.org` — синтетические примеры.

После изменения CSV выполните `npm.cmd run seed` и обновите страницу. Seed синхронизирует записи `demo-*` с CSV, включая исходные статусы откликов и опубликованные карточки. Повторная загрузка не создаёт дубликатов. Созданные через сайт задачи сохраняются. Старые неизменённые встроенные примеры удаляются; изменённые примеры или записи с пользовательскими связями сохраняются.

В автономном режиме CSV включаются в сборку Vite. Изменение набора обновляет начальные примеры; пользовательские добавления хранятся отдельно в браузере, прежний кеш сохраняется как резервная копия. Для опубликованной сборки после изменения CSV нужна повторная `npm.cmd run build`.

## AI и сценарий

Без `OPENAI_API_KEY` сервер использует шаблонные вопросы (`mode: "template"`), поэтому весь сценарий работает локально. Для живой генерации добавьте ключ **только** в `server/.env`; frontend его не получает. `AI_MODE=template` принудительно включает локальный режим. Сервер ограничивает число вызовов и бюджет, при сбое AI возвращается к шаблону. `node:sqlite` может показать экспериментальное предупреждение Node.js.

Бизнес описывает проблему, получает предложенную карточку и 3–5 уточнений, проверяет сведения и публикует задание. Запись создаётся после содержательного ввода. Ответы сразу дополняют карточку, ручные правки защищены от повторной генерации, источник предложения можно раскрыть рядом с полем. Неизвестные сведения остаются неизвестными. Шаблонный режим явно обозначен.

Изменения сохраняются автоматически; текущая задача и этап доступны по ссылке `#/tasks/:id?step=review`. Незавершённый ввод восстанавливается из локальной копии браузера, сохранённая карточка и AI-предложение — с сервера. При конфликте версий доступны объединение правок и загрузка версии сервера. Работа с черновиком, подтверждение и публикация используют разные снимки: студенты увидят изменения только после явного обновления публикации. Полнота черновика показана отдельно от подтверждённого рейтинга.

Команда открывает каталог, фильтрует задачи по теме и готовности, читает полную страницу задания и отправляет идею, план, срок и ссылку на прототип. Бизнес сравнивает 2–3 отклика на одну задачу и принимает решение по каждому; можно выбрать несколько команд. Низкий рейтинг не блокирует публикацию или отклик.

Интерфейс: белый фон, синие акценты и один системный шрифт Segoe UI / system-ui. Навигация расположена сверху, на узком экране колонки переходят в последовательные блоки. Основной текст 16 px, вспомогательные подписи 12–14 px. Внешние шрифты не загружаются.

Сервер сохраняет последнее AI-предложение вместе с цитатами источников и предупреждениями. После изменения исходных данных оно помечается устаревшим. После обновления кода перезапустите backend: новые колонки SQLite добавятся автоматически, существующие задачи сохранятся, повторный seed не нужен.

## Проверка

```powershell
npm.cmd test
npm.cmd run build
```

Проверки сервера проходят сквозной HTTP-сценарий с временной SQLite, миграцию старых данных, разграничение доступа, опубликованные снимки и источники AI. Тесты `test/editor-model.test.ts` проверяют объединение предложений, ручные правки, неизвестные ответы и конфликты версий. Живой OpenAI требует ключ и отдельно не тестируется.

Короткий сценарий демонстрации и критерии реализации: [docs/CASE.md](docs/CASE.md).
