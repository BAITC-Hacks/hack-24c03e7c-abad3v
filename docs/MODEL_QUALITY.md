# Проверка качества AI — 23 сентября 2026

Проверена настоящая `gpt-6-sol` через тот же `liveResult`, промпт и валидаторы, которые использует приложение. Это небольшой исходный прогон, а не доказательство стабильности на любых задачах. Промпт и поведение продукта в рамках проверки не менялись.

## Условия и результат

- Код приложения: `8d2fac3`, промпт `v5-guided-answers`, `reasoning.effort=none`.
- 8 синтетических сценариев: 6 генераций вопросов и 2 сборки карточки. Один вызов на сценарий, без повторов и без LLM-судьи.
- **8 ответов от API; 7 приняты приложением, 1 отклонён валидатором.** Сбоев сети, таймаутов и обрезанных ответов не наблюдалось. При этом отклонённый ответ в обычном HTTP-сценарии привёл бы к шаблонному режиму; сам eval шаблон не запускал.
- 41 базовая автоматическая проверка принятых ответов прошла. Это проверки отдельных значений и неизвестных полей, а не 41 проверка качества текста. Вопросы, варианты и смысл фактов просмотрены отдельно.
- Задержка вызова: 3,94–11,67 секунды, медиана 7,34 секунды. Один вызов близок к текущему таймауту 12 секунд.
- 6 980 входных и 5 236 выходных токенов. Оценка расхода **$0,06632** при лимите запуска $0,50. Это локальная оценка без скидки за кеш, не выписка биллинга. Тарифы $2/$10 за миллион входных/выходных токенов сверены с [официальной страницей модели](https://developers.openai.com/api/docs/models/gpt-6-sol).
- Полные синтетические входы, исходный JSON модели и результат обработки: [снимок прогона](evals/2026-09-23-baseline.json).

## Что исправлять сначала

1. **Не терять качественно извлечённую карточку из-за количества вопросов.** Сейчас `server/src/ai.js` требует минимум три вопроса и отвергает весь результат, если их нет. Нужно отдельно валидировать факты и уточнения. По текущему CASE минимум 3–5 вопросов сохраняется: для полного описания это должны быть точные уточнения ещё не определённых деталей, а не повтор уже известных сроков и данных. Если вопросы приходится дополнять локально, происхождение дополнения нужно показывать честно. Просто ослабить правило до нуля без согласования требований — не исправление.
2. **Согласовать варианты с текстом вопроса.** `shared/question-options.js` заменяет все варианты `contact.consultation` и `contact.feedback` на фиксированные локальные. Реальный пример: модель спросила «Кто сможет консультировать?» и предложила «Преподаватель / Представитель заказчика / Пока неизвестно». После обработки появились «Письменные уточнения / Короткие встречи / Проверка по этапам». Это ошибка приложения, а не модели. Требуются варианты, отвечающие на «кто», «как часто», «как» и «возможно ли» соответственно, с сохранением отрицательного ответа и неизвестности.
3. **Стабильно предлагать название как краткое резюме известных сведений.** В четырёх из пяти принятых анализов название пустое. Публикация требует название; пользователь получает лишнюю ручную работу. Промпт должен разрешать краткую переформулировку с цитатой, не добавляя неподтверждённых фактов.
4. **Усилить проверяемость критериев.** Варианты «показать демонстрацию» или «получить отзывы» описывают процесс, но слабо определяют результат. Лучше «доля записей без двойного бронирования», «совпадение найденных ошибок с разметкой преподавателя», «время поиска». Числовой порог по-прежнему задаёт пользователь.

Один лишь переход на другую модель не устранит первые два дефекта. Для них нужны изменения обработки ответа и нормализации вариантов. После правок сначала повторить проблемные сценарии, затем весь набор несколькими проходами и на новых описаниях.

## Повторение

Из корня проекта:

```powershell
# Только список сценариев, без API и оплаты
npm.cmd run eval:ai

# Живая проверка, максимум $0,50 по внутреннему расчёту
npm.cmd run eval:ai -- --live --budget=0.50

# Отдельные проблемные сценарии
npm.cmd run eval:ai -- --live --budget=0.20 --case=rooms-complete,instruction-in-data
```

Нужен ключ в `server/.env`, модель из списка бюджетируемых моделей и `AI_MODE`, отличный от `template`. Вызовы учитываются в общей таблице `ai_usage`; неизвестный расход учитывается по консервативному резерву. Задачи и публикации для eval не создаются. Не совмещать с другими платными AI-сессиями: у HTTP-приложения отдельный путь резервирования бюджета. При двух ошибках провайдера либо ошибке настройки/доступа/лимита прогон останавливается.

Сохранённый baseline был создан первой версией runner: ревизия кода указана выше; следующие отчёты дополнительно сохраняют Git SHA и контракт запроса. Данные в файлах синтетические. Платный прогон намеренно не входит в `npm.cmd test`.

Ограничения: проверена граница генерации и обработки ответа, не весь браузерный путь; один запуск не измеряет частоту ошибок; смысловое соответствие цитаты факту проверяется вручную. Автоматические проверки могут пропустить пустую/неполную карточку или слабые вопросы, поэтому их успешность не является общим баллом качества. Обычные проверки проекта отдельно завершились успешно: 48 backend + 37 frontend тестов, production-сборка.
